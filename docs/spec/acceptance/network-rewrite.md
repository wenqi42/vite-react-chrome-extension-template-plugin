# Network Rewrite 运行时验收

范围：`examples/network-rewrite-extension` 的标签页附加、响应改写、沙箱脚本与状态反馈。使用本仓库插件生成产物。

允许实现修改：该示例目录；如需新增验证命令，可修改根目录 `package.json` 的 scripts 和 `scripts/`。禁止扩大至插件 API 或生成器重构。

## 成功标准

1. 独立 Chrome for Testing 配置加载构建产物，扩展 worker、侧栏页面、offscreen document 和 sandbox iframe 能正常运行。
2. 未附加时明确提示不能拦截；保存规则不能显示成已开始拦截。附加普通 HTTP/HTTPS 标签页后显示准确状态，拒绝受限制页面并显示可理解的错误。
3. 附加后新发起的匹配 Fetch/XHR 响应中，Header 脚本可增加、删除、修改 header；Body 脚本可修改 UTF-8 文本及 JSON。页面实际收到修改结果，不以编辑器内容或 mock 代替。
4. 不匹配或禁用规则保留原始响应。Detach 后请求恢复原始响应。
5. 脚本异常或异步超时不阻塞请求，并将错误反馈到侧栏；用户可区分未附加、未命中、改写成功和改写失败。
6. 已持久化规则在重开侧栏后可读，UI 的附加状态能跟随后台分离变化，不覆写未保存的输入。
7. Header-only 改写保留二进制原文；正文变化时移除旧的内容长度和编码 header，避免响应损坏。无正文和重定向响应不得卡住。
8. TypeScript、现有单元测试、构建和产物验证通过。行为修复包含有意义的回归检查。

## 失败标准

- 只验证 HTTP 预览，未加载真实扩展。
- 页面收到原始正文却报告改写成功，或失败后请求一直 pending。
- 后台发生未处理异常，或侧栏长期显示过期的附加状态。
- 用“用户必须已点击 Attach”替代实际端到端验证。

## 验收报告

独立 Verifier 给出 PASS、FAIL 或 BLOCKED，并提供命令、Chrome 版本、实际响应断言和已观察的运行时上下文。浏览器功能限制和未覆盖边界应明确列出。
